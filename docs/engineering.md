# From marks to records

## A candidate physical primer

A reader first needs to find a surface, resolve individual marks and infer an order. A proposed primer begins with large repeated marks next to groups of one, two, four and eight squares. Beside these groups, show the same counts in binary with the high-order bit visibly aligned. Pair a short sequence of marked and empty cells with an enlarged rendering of its corresponding picture. Put an asymmetric corner marker on each grid and repeat a panel at a second scale. A full specimen would need diagrams etched directly beside the data. The current English guide begins later, after byte recovery.

## Archive layers and reader assumptions

| Layer | Input and output | Prototype evidence |
| --- | --- | --- |
| Physical | Surface contrast and spatial scale to ordered cells | Proposed panel sequence only |
| Framing | Cells to octets, row boundaries and addresses | Proposed high-order-bit-first example; no physical interchange standard selected |
| Digital | Recovered ZIP bytes to an inventory and files | Build, inspect and verify commands; independent ZIP readers |
| Interpretation | Samples to pictures, procedures and cultural records | Grayscale plate, prose and weaving table; English literacy assumed for prose |

In the weaving table each row is one pass of the crosswise thread. Columns run from the first lengthwise thread to the fourth. “Over” places the crosswise thread above that thread when viewed from one face. This definition illustrates how much prior knowledge even a four-by-four record requires.

## Redundancy and recovery

The digital prototype carries one copy of each file. ZIP CRCs and manifest SHA-256 digests detect damage; they cannot reconstruct lost bytes. For a physical experiment, consider spatially separated primer copies, duplicated indexes and parity across interleaved data blocks. Keep a reference copy on Earth. A scratch spanning adjacent cells and a missing whole panel are different failure models. Test both before choosing block size, copy spacing or parity overhead.

## Decisions that require evidence

| Unknown | Evidence needed before a payload proposal |
| --- | --- |
| Carrier, feature pitch and readout | Etched coupons, microscopy at several contrasts, blinded decoding and bit error counts |
| Durability | Mission-specific environment and duration, thermal and radiation exposure tests, post-test readability |
| Allocation and integration | Mission team's mass, volume, mounting and handling constraints; measured assembly properties |
| Recovery budget | Damage maps, simulated erasures and measured recoverable fraction per added byte |
| Meaning and curation | Independent readers attempting the primer, multilingual review, provenance and consent for future contributions |

No flight hardware, test campaign or mission interface is established. The 1–10 MB target is a software design budget. A byte count alone gives no physical area or survival estimate.
